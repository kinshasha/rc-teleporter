# IC-PCR1000 web remote prototype

The PCR1000 prototype runs in the existing gateway process. It uses the same
audio capture, WebRTC/TURN configuration, and two listener ports as the
Uniden interface:

```text
Icom IC-PCR1000 -- USB-to-serial --> Mac serial device
PCR1000 line output -- 3.5 mm --> Mac USB audio interface
                                      |
                                      +-- :3000 operator console
                                      +-- :3001 listen-only console
```

`3000` is the operator interface. It can tune frequency, set mode and filter,
set receiver volume and squelch, toggle AGC/AFC/noise blanker/attenuator, and
choose the Mac audio device.

`3001` is a view/listen-only interface. It receives last-commanded receiver
state and the same low-latency WebRTC audio stream, but the server rejects the
control WebSocket and does not expose any PCR1000 command route.

## First hardware connection

The PCR1000 begins serial control at 9600 bps. Its protocol uses LF (`\n`), not
the CR terminator used by Uniden scanners. Configure it explicitly rather than
using automatic serial-port selection:

```json
{
  "rcScanner": {
    "model": "pcr1000",
    "com": {
      "port": "/dev/tty.usbserial-XXXXXXXX",
      "baudRate": 9600,
      "dataBits": 8,
      "parity": "none",
      "stopBits": 1,
      "rtscts": true,
      "terminator": "\n"
    }
  }
}
```

Use the actual `/dev/tty.*` path reported by `npm run list-ports`. Do not set
the gateway to 38,400 bps until the PCR1000 has been validated at 9600 bps;
the receiver starts at 9600 after power-up.

## Supported prototype controls

The server validates each browser request before generating a serial command:

- Frequency from 10 kHz to 1.3 GHz via `K0...`.
- AM, CW, FM, LSB, USB, and WFM modes with compatible 2.8/6/15/50/230 kHz filters.
- AF volume (`J40xx`) and squelch (`J41xx`) between `00` and `FF`.
- AGC (`J45xx`), noise blanker (`J46xx`), 20 dB attenuator (`J47xx`), AFC (`LD820xx`), and receiver standby (`H100`/`H101`).

The PCR1000 protocol has limited settings readback. The panel therefore labels
its state as **last commanded state**, not live receiver confirmation. Hamlib's
PCR backend is the protocol reference for this initial implementation.

## Cloudflare tunnel

Keep separate hostnames and Access policies, as with the Uniden deployment:

```yaml
ingress:
  - hostname: pcr.example.com
    service: http://mac-lan-address:3000
  - hostname: listen-pcr.example.com
    service: http://mac-lan-address:3001
```

Restrict `pcr.example.com` to operators. Give listeners access only to
`listen-pcr.example.com`. Cloudflare Access controls who may connect; the
gateway is still the authority that prevents control traffic on port `3001`.

## Validation before use

1. Start with the receiver disconnected and set `model` to `pcr1000`; the web console should render on both ports.
2. Connect serial only and confirm the server identifies the intended port.
3. Test a single known receive frequency and mode at 9600 bps.
4. Connect the receiver's line output through a USB audio interface and select it on `3000`.
5. Confirm WebRTC audio locally, then through the `3001` listener hostname.
